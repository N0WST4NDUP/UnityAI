# OBSERVATIONS.md

Agent별 Observation Space 설계. Phase 2~3 구현의 기준이 된다.

> **2026-04-20 Feudal HRL 재설계 반영** — 유닛 관측에 `CurrentCommand` + `분대 동료 상태` 포함. 커맨더는 완전 정보 시작 (시야 제한은 Phase 3+ 연구 과제).

---

## 0. 설계 원칙

| 원칙 | 설명 |
|---|---|
| 고정 크기 | 유닛 수 변동에 관계없이 관측 벡터 크기 불변. 빈 슬롯은 0 패딩 + 존재 flag. |
| 정규화 | 좌표·HP·거리 등 모든 수치는 0~1 또는 -1~1 범위로 정규화. |
| 상대 좌표 | 유닛 관측의 타 유닛/구조물 위치는 **자기 기준 상대 좌표** (회전 불변성↑). |
| 명령은 관측 | 유닛은 커맨더 명령을 "외부 상태"로 수신. 이게 커맨더-유닛 분리의 인터페이스. |

## 1. Unit Agent Observation

### 1-1. 구조 개요

```
[자기 상태]          → 본인 HP/위치/직군/쿨타임
[CurrentCommand]     → 자기 분대의 현재 명령 (3필드)
[분대 동료 상태]     → 같은 분대 유닛들의 위치/HP
[지역 관측 - Vector] → 주변 적/구조물 최근접 정보
[지역 관측 - Ray]    → 부채꼴 RaySensor
[시너지 flag]        → 팀 시너지 (Phase 2 중후반)
```

### 1-2. VectorSensor 인덱스 맵 (초안)

| 인덱스 | 내용 | 크기 | 정규화 |
|---|---|---|---|

**총 크기**: 64차원 (초안)

### 1-3. RaySensor

| 설정 | 값 (초안) | 비고 |
|---|---|---|
| Ray 개수 | 16 | 전방 180° 부채꼴 |
| 감지 각도 | 180° (전방) | 후방은 VectorSensor에서 커버 |
| 최대 거리 | 맵 대각선의 1/4 | 실험 후 조정 |
| 감지 태그 | Enemy, Ally, Structure, Barricade | 4채널 |

### 1-4. 명령 인코딩 세부

- **priority_filter**: `IgnoreAll`은 "교전 회피 이동"에 사용 (우회 시나리오). 이 경우 타겟 매치 보상은 무효.
- **structure_handling**: `Detour`와 `Ignore` 차이 — `Detour`는 경로 수정 유도 (공격 금지), `Ignore`는 공격 안 하되 우회 보상도 없음.
- 명령이 갱신되면 `경과 시간`이 0으로 리셋.

### 1-5. 적군 관측 제한

- 적군은 **지역 관측 슬롯**(최근접 3명)만 본다. 적 전체 상태는 커맨더가 인식해서 **명령으로 추상화**해서 전달한다는 원칙.
- 이게 "군대식 체계" 연출의 핵심.

## 2. Commander Agent Observation

### 2-1. 기본 방침 — 완전 정보

- 아군·적군·구조물·지형 **모두** 관측.
- 안개 전쟁(시야 제한)은 Phase 3+ 연구 과제로 분리.
- 이유: 초기 학습 안정성. 완전 정보에서도 전략 복잡성은 충분.

### 2-2. VectorSensor 인덱스 맵 (초안)

```
[전장 메타]
[아군 유닛 N 슬롯]
[적군 유닛 N 슬롯]
[아군 구조물 M 슬롯]
[적 구조물 M 슬롯]
[아군 분대 현재 명령]
[라운드 정보]
```

| 섹션 | 내용 | 크기 (예) |
|---|---|---|
| 전장 메타 | 아군 수 / 적군 수 / 아군 구조물 수 / 적 구조물 수 / 경과 시간 | 5 |
| 아군 유닛 × N=10 | 존재flag, HP, 위치(x,z), 직군, 소속 SquadId, 현재 교전 여부 | 7 × 10 = 70 |
| 적군 유닛 × N=10 | 존재flag, HP, 위치(x,z), 직군, 현재 교전 여부 | 6 × 10 = 60 |
| 아군 구조물 × M=5 | 존재flag, 내구도%, 위치(x,z) | 4 × 5 = 20 |
| 적 구조물 × M=5 | 동일 | 4 × 5 = 20 |
| 아군 분대 명령 × S=4 | 현재 명령 3필드 인코딩 | 11 × 4 = 44 |
| 라운드 | 공성/수성 flag, 라운드 번호, 남은 시간 | 3 |
| **총 크기** | | ~222 |

> 실제 크기는 팀당 유닛/구조물/분대 수 확정 후 고정. N/M/S는 최대값.

### 2-3. Grid 오버레이 (선택, Phase 3 실험)

완전 정보 VectorSensor로 학습이 어렵거나 공간 관계 파악이 약할 경우 **GridSensor 오버레이**를 추가 실험.

- 맵을 NxN Grid(예: 16x16)로 나눔
- 각 셀 채널:
  - 아군 유닛 수
  - 적 유닛 수
  - 아군 구조물 유무
  - 적 구조물 유무
  - 지형 높이
- CNN 기반 공간 인식 활용

> **Phase 3 TASK-301**에서 VectorSensor 단독 vs Grid 오버레이 병행 비교 실험.

## 4. 시너지 flag 상세 (Phase 2 중후반)

유닛 관측 인덱스 60~63에 삽입.

| Bit | 시너지 | 활성 조건 |
|---|---|---|
| 60 | 공격적 | 팀에 Dealer 4명 이상 |
| 61 | 수비적 | 팀에 Tank 3명 이상 |
| 62 | 은신 | 팀에 Assassin 2명 이상 |
| 63 | 마법 | 팀에 Mage 3명 이상 |

> 시너지 목록은 Phase 2 중후반에 재검토. flag 추가 시 관측 크기 확장 → ONNX 재학습 필요.

## 5. 주의사항

- 관측 크기 변경 시 **기존 ONNX 폐기 → 재학습 필요**.
- 분대 동료 슬롯 최대치는 분대 크기 상한과 연동 (현재 4명 가정).
- 최근접 적/구조물 슬롯은 **거리 정렬 후 상위 K개** — 정렬 기준이 학습에 영향.
- NavMesh 기반 자유 이동이므로 Grid 셀 인덱스는 **사용하지 않음**. 모두 월드 좌표.

# Phase 4 — 아이템 + 구조물 확장

> **2026-04-20 Feudal HRL 재설계 반영** — 아이템/지형은 유닛 관측과 커맨더 관측에 각각 반영. 지형 편집은 커맨더 준비 페이즈 정책(TASK-313)과 연계.

## 목표

전투 중 유저 개입 시스템(바리케이드, 포탄)과 준비 페이즈 지형 편집, 구조물 종류 확장을 구현한다.

## 선행 조건 (의존 Phase)
- Phase 3 완료 (커맨더 RL 학습 완료, Squad/Command 구조 안정)
- Phase 1의 NavMesh 시스템이 안정적으로 동작

## 세부 Task 목록

### TASK-401: 바리케이드 시스템
- 구현 위치: `Assets/Scripts/Items/Barricade.cs`
- 방식: 자유 좌표 + 방향 회전 + NavMeshObstacle(Carve=true)
- 관측 반영:
  - 유닛 관측: 최근접 구조물 슬롯에 "구조물/바리케이드" 태그로 포함 (OBSERVATIONS.md §1-2 52-59)
  - 커맨더 관측: 아군/적 구조물 슬롯 확장 또는 별도 바리케이드 슬롯 추가
- 완료 조건:
  - 전투 중 클릭으로 바리케이드 배치 (유저 개입)
  - NavMesh 실시간 갱신 → 유닛 경로 재계산
  - 유닛 Agent가 인식하고 경로 수정
  - 커맨더가 바리케이드 정보를 활용해 명령 수정

### TASK-402: 포탄 투하 시스템
- 구현 위치: `Assets/Scripts/Items/Bombardment.cs`
- 방식: 자유 좌표 AoE, 낙하 예고 시각 표시 → N초 후 폭발
- 관측 반영:
  - 유닛 관측: "위험 영역" 슬롯 신설 (상대 좌표 + 남은 시간)
  - 커맨더 관측: 예고 영역 위치·반경
- 완료 조건:
  - 낙하 예고 원형 표시 + 폭발 데미지
  - 유닛 Agent가 예고 영역을 회피 경로로 학습
  - 관측 크기 확장에 따른 ONNX 재학습

### TASK-403: 아이템 사용 UI
- 구현 위치: `Assets/Scripts/UI/ItemPanel.cs`
- 완료 조건: 전투 중 아이템 선택 + 좌표 지정 + 사용 UI 동작

### TASK-404: 지형 편집 시스템 (준비 페이즈)
- 구현 위치: `Assets/Scripts/Terrain/TerrainEditor.cs`
- 방식: 준비 페이즈에서 수성 측 진영 높낮이 조절 (타이쿤류)
- 커맨더 정책 연계:
  - TASK-313(분대 편성 정책)과 동일한 준비 페이즈 액션
  - **지형 편집 액션**을 커맨더 준비 정책에 추가할지 여부 Phase 3 결과 보고 결정
  - 초기엔 수동(유저) 편집, 커맨더 학습 대상에서 제외 고려
- 완료 조건:
  - 마우스로 지형 높낮이 조절 (범위/높이 제한)
  - 전투 시작 시 NavMesh Bake에 반영
  - 전투 중 변경 불가

### TASK-405: 구조물 종류 확장
- 확장 종류: 문(Gate), 탑(Tower), 계단(Stairs), 사다리(Ladder) 등
- 각 구조물 고유 특성:
  - 문: 내구도 낮음 + 파괴 시 큰 통로 생성
  - 탑: 공격 가능 (Tower 자체가 IAttackable? 또는 유닛 상주?)
  - 계단/사다리: NavMesh 연결 (높낮이 넘기)
- SquadCommand 영향:
  - `structure_handling` enum 확장 검토 (특정 구조물 타입 우선 파괴 등)
- 완료 조건:
  - 각 구조물 특성 동작
  - NavMesh와 올바른 상호작용

## 주의사항

- **바리케이드/포탄은 observation 확장 필요** → 관측 크기 변경 → ONNX 재학습.
- **지형 편집을 커맨더 학습에 포함할지**는 Phase 3 결과 보고 결정. 포함 시 준비 페이즈 정책 복잡도↑.
- 구조물 종류 확장 시 `structure_handling` enum도 함께 확장 고려.
- 새 관측 슬롯은 OBSERVATIONS.md에 인덱스 맵 즉시 업데이트.
